# Data

A synthetic HIE dataset generated by [Synthea](https://github.com/synthetichealth/synthea). None of it is real patient data.

```sh
tar -xJf data/synthea_sample_data_fhir_latest.tar.xz -C data --strip-components=1
```

## Files

| File | Contents |
|---|---|
| `<Given>_<Family>_<uuid>.json` | One patient's full medical history as a FHIR Bundle. There are 109 of these |
| `hospitalInformation*.json` | Hospitals and clinics, shared by all patients |
| `practitionerInformation*.json` | Doctors and other clinicians, shared by all patients |

Patients range from a newborn with a few visits to someone with decades of chronic illness. The smallest file is 100 KB, and the biggest is 52 MB. About half of them are too big to fit in a model's context window as-is.

## Resources

[FHIR](https://hl7.org/fhir/R4/) (Fast Healthcare Interoperability Resources) is the standard format health systems use to exchange records. A record is a **resource**, a JSON object with a `resourceType` and an `id`. Resources point to each other with references: an Observation's `subject` is the Patient and its `encounter` is the visit where it was measured. A **Bundle** is a list of resources in `entry[].resource`. Each field is defined in the resource's spec page, for example [Observation](https://hl7.org/fhir/R4/observation.html). References inside a patient bundle look like `urn:uuid:<id>` and match another entry's `fullUrl`. References to a Practitioner or Organization look like `Practitioner?identifier=http://hl7.org/fhir/sid/us-npi|<npi>`, and you resolve them by that identifier in the two shared files, not by `id`.

| Group | Resource | What it is |
|---|---|---|
| Who | Patient | Demographics: name, birth date, sex, address, and death date if deceased |
| Who | Practitioner, PractitionerRole | Clinicians, and the organization each one works for (from the shared file) |
| Who | Organization, Location | Hospitals, clinics, and payers (from the shared file) |
| Who | CareTeam | The clinicians responsible for a care plan |
| Visits | Encounter | One visit: when, where, who saw the patient, and why. Most clinical resources point back to one |
| Problems | Condition | A diagnosis or problem, with onset and (if resolved) abatement dates. SNOMED-coded |
| Problems | AllergyIntolerance | An allergy and the reaction it causes |
| Measurements | Observation | One measured value: a vital sign, lab result, or survey score. LOINC-coded, usually a `valueQuantity` with UCUM units |
| Measurements | DiagnosticReport | Groups related Observations (for example a lab panel). Some also carry the note text in `presentedForm` |
| Measurements | ImagingStudy | Metadata about an imaging study. No images |
| Treatment | MedicationRequest | A prescription. RxNorm-coded |
| Treatment | Medication, MedicationAdministration | A drug, and a record of it being given during a visit |
| Treatment | Procedure | Something done to the patient, like surgery, a screening, or counseling. SNOMED-coded |
| Treatment | Immunization | A vaccine given. CVX-coded |
| Treatment | CarePlan | Planned activities for a condition |
| Treatment | Device, SupplyDelivery | Implanted or supplied devices, and supplies delivered |
| Notes | DocumentReference | A clinical note as base64 text, one per encounter |
| Billing | Claim, ExplanationOfBenefit | What was billed for a visit and how the insurer handled it |
| Metadata | Provenance | Who created the bundle's records, and when |
